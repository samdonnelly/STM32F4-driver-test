# STM32F4 Driver Test 

Application/hardware test code for the STM32F4 series of microcontrollers. Most of the tests are for the drivers and tools in the <a href="https://github.com/samdonnelly/STM32F4-driver-library">STM32F4-driver-library</a> but there are also some specific use case tests. This repository is used for checking how code runs on hardware before using it in an application. Tests also serve as example code that can be referred to later on. 

The default branch ('template') of this repository acts as a template for creating new projects using this platform. Please refer to the "How to Use" section below for more information in using this code. 

## Driver Tests 

Test code is written for the device drivers, peripheral drivers and software tools in the <a href="https://github.com/samdonnelly/STM32F4-driver-library">STM32F4-driver-library</a>. These tests focus on showing how to use each driver as opposed to applying it to a specific application.

Peripheral Driver Tests: <a href="https://github.com/samdonnelly/STM32F4-driver-test/tree/template/sources/peripheral_test">src</a>, <a href="https://github.com/samdonnelly/STM32F4-driver-test/tree/template/headers/peripheral_test">inc</a> \

These tests still use code from the <a href="https://github.com/samdonnelly/STM32F4-driver-library">STM32F4-driver-library</a> but their focus is on applying the code to a use case as opposed to showing how the drivers and software tools work.

## How to Use 

### Dependencies 

This project requires the <a href="https://github.com/samdonnelly/STM32F4-driver-library">STM32F4-driver-library</a>. If cloning this repository or using it to create a new STM32F4 project, be sure to also clone the library and include it in your workspace and build filies. 

### Where to put Code 

The main file is located in the <a href="https://github.com/samdonnelly/STM32F4-driver-test/tree/template/sources/core">core</a> folder but a user should add calls to test code in the <a href="https://github.com/samdonnelly/STM32F4-driver-test/blob/template/sources/project_init.cpp">project_init</a> and <a href="https://github.com/samdonnelly/STM32F4-driver-test/blob/template/sources/project_app.cpp">project_app</a> files as these are referenced by main to carry out initialization and application code, respectfully. The project_init and project_app functions should be empty in the default branch. 

### System Configuration 

Since this repository contains a variety of test cases and hardware, the project will need to be configured in a specific way. This is handled through the use of a "system_config.h" file. This file is not tracked because it contains settings specific to the user and not the repository. This means that when creating a local copy of this repository, the user must create their own "system_config.h" file. Refer to the <a href="https://github.com/samdonnelly/STM32F4-driver-test/blob/template/headers/core/system_config_template.h">system_config_template</a> for instructions on creating this file and details on what settings are included.
